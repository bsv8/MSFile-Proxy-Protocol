# 20260825-2 MSFile NAS V1 一次性硬切换施工单

> 类型：一次性迭代施工单，硬切换，不分阶段上线。
>
> 需求真值：[MSFile NAS V1 需求冻结](./20260825-1-MSFile-NAS-V1需求冻结.md)。
>
> 协议真值：[Wire Messages V1](../protocol/wire-messages.zh.md)、
> [Network Protocol V1](../protocol/network.zh.md)。

## 1. 施工目标

在一次迭代内把 Go NAS 从实验/对象仓库方向完整替换为以下最终外形：

```text
nas_data
  = 用户原目录和原文件真值
  = 服务只读，不改变布局

seed_data
  = MasterSeed + SQLite 平面 Hash 索引 + 临时运行状态
  = 可以从 nas_data 重建

同步
  = 递归文件事件快速发现 + 周期全量扫描最终收敛

访问
  = private 配置文件公钥列表 / public 任意已认证公钥

网络
  = WebRTC Direct + WS/WSS 上的 libp2p /msfile/1.0.0

管理
  = 中文平面 Hash 运维页面，无目录树、无白名单管理、无原文件写操作
```

本施工单完成前不得把其中任一中间状态标记为可交付版本。

## 2. 为什么使用硬切换

### 2.1 原因

旧方向与冻结需求在数据真值上互斥：

| 旧方向 | 最终方向 |
|---|---|
| 导入文件后生成独立块对象 | 原文件保留在 `nas_data`，块按偏移读取 |
| 服务管理文件上传/删除 | 用户通过挂载管理原文件，服务只建立分享索引 |
| SQLite 保存客户端白名单 | 白名单只是配置文件中的公钥数组 |
| 空白名单可能 allow-all | 只有显式 `access_mode: public` 才公开 |
| Web 管理白名单和文件变更 | Web 只查询 Hash/同步状态并触发扫描 |

若做渐进兼容，将同时出现两种原文件来源、两套删除语义、两种授权真值和两种块读取路径，无法
证明 Stat `available` 与 Read 内容一致。`seed_data` 本来就是可重建派生数据，因此保留旧索引兼容
层的收益低于错误服务内容的风险。

### 2.2 硬切换定义

硬切换表示一个 release 同时完成并启用：

- 新配置格式；
- 新 SQLite schema；
- 新 `nas_data`/`seed_data` 存储语义；
- 新同步协调器；
- 新读取路径；
- 新 private/public 授权；
- 新 Web 运维面；
- 正式 MSFile 网络服务。

不允许：

- 先上线 watcher、以后补全量扫描；
- 先使用旧对象仓库提供 Read、以后切原文件 ReadAt；
- 同一个 binary 按旧/新 flag 双模式运行；
- 对同一个文件同时写旧 objects 和新 `.seed`；
- 在生产流量中灰度两套 SQLite schema；
- 以“暂时兼容”为名保留空白名单 allow-all。

施工可以按代码依赖顺序开发，但只有最终 Gate 全部通过后才能一次性切换运行。

## 3. 切换前提与 Gate 0

编码前必须完成并记录：

1. 确认当前 `/msfile/1.0.0` 文档仍是协议真值；
2. 锁定 Go、go-libp2p、SQLite driver、fsnotify 和 YAML parser 的正式版本；
3. 确认目标操作系统的 watcher 行为，明确网络挂载事件可能缺失；
4. 确认 `nas_data` 与 `seed_data` 不能互相包含；
5. 确认 V1 最大原文件尺寸仍由 16 MiB Seed 与 256 KiB 块推导为 128 GiB；
6. 准备至少一个本地文件系统测试目录和一个目标 NAS 挂载类型的人工测试目录；
7. 记录旧实验数据没有生产迁移承诺；有旧 `data/objects` 或旧 SQLite 时先备份，不自动删除。

任一协议字段需要改变时停止施工，先更新协议版本和需求文档，不能在实现里私自兼容。

### 5.5 扫描、watcher、稳定性与回收

| 文件 | 动作 | 怎么做 | 不能怎么做 |
|---|---|---|---|
| `internal/library/coordinator.go` | 新增 | 统一 path revision、Hash 队列、提交、启动/停止生命周期 | watcher 和 scanner 各自提交产生竞态 |
| `scanner.go` | 新增 | generation 全量扫描、失败范围转 invalid、周期调度 | 一次 Walk 错误就删除全部未见路径或继续声称 available |
| `watcher.go` | 新增 | 递归目录 watch、事件防抖、overflow 触发扫描 | 假设网络挂载事件完整可靠 |
| `stabilizer.go` | 新增 | stat A/B/C、安静期、revision 失效判断 | 正在写入时发布 available |
| `gc.go` | 新增 | 24 小时失效清理、引用检查、Seed 移入 trash | 删除 nas_data 原文件或刷新 invalid_since |
| 对应测试 | 新增 | fake clock、fake watcher、临时树、事件乱序、partial scan | 依赖真实等待 24 小时 |

Coordinator 必须限制：

- Hash worker 数；
- 待处理路径队列长度；
- 同一路径同时只有一个有效 revision；
- 停止时不再开始新 Hash；
- 已完成但 revision 过期的结果只能清理临时文件，不能提交。

允许的 V1 API 最小集合：

```text
GET  /api/status             服务与扫描状态
GET  /api/files              public 模式平面 Hash 查询
GET  /api/files/{seed_hash}  public 模式单 Hash 详情；不得返回绝对路径
GET  /api/scans              最近扫描结果
POST /api/scans              触发一次全量扫描
```

其他写方法返回 `405 Method Not Allowed`。`access_mode: private`（`public_key_whitelist` 白名单模式）
下，文件列表、详情和下载接口返回 `403 content_index_disabled`；`access_mode: public` 不改变管理 API
的认证要求。

| 文件 | 动作 | 怎么做 | 不能怎么做 |
|---|---|---|---|
| `internal/nas/nas.go` | 替换 | config -> lock -> DB -> policy -> coordinator -> libp2p/admin -> shutdown | 在组合根重新实现 SQL、扫描和 Hash |
| `internal/nas/nas_test.go` | 新增 | 启停顺序、失败回滚、第二实例锁拒绝、优雅停止 | goroutine 泄漏或先开 listener 后验证配置 |

建议启动顺序：

```text
解析并完整验证配置
  -> 创建/检查 seed_data
  -> 取得 service.lock
  -> 打开并验证 SQLite schema
  -> 创建只读 auth policy
  -> 恢复未完成 scan/staging/trash
  -> 启动 coordinator，安排首次全量扫描
  -> 注册 /msfile/1.0.0
  -> 启动 WebRTC Direct + WS/WSS listener
  -> 启动 loopback Web 管理面
```

建议停止顺序：

```text
停止接受新管理任务和新 libp2p stream
  -> 停止 watcher/周期扫描
  -> 停止产生新 Hash 任务
  -> 取消或有界等待现有 worker
  -> drain SQLite executor
  -> 关闭 host/http/db
  -> 释放 service.lock
```

## 6. 必须删除或禁止继续使用的旧能力

硬切换提交必须删除代码或彻底移出正式 binary：

```text
internal/storage 中的 objects 块仓库语义
files + objects + file_objects 旧 schema
clients SQLite 表和 Permission DB 查询
Web POST/DELETE /api/files
Web GET/POST/DELETE /api/clients
Web 白名单表单与按钮
命令行 --allow-public-key 作为另一套持久化来源
未配置白名单自动 allow-all

```

实验 binary 可以继续拥有实验协议，但不得打开正式 `seed_data/index.sqlite` 或扫描 `nas_data`。

## 7. 一次性切换执行方式

这不是多阶段实施，而是最终 release 的原子运维切换：

1. 停止旧 NAS 进程，确认没有旧进程持有端口或数据目录；
2. 备份旧配置、旧数据库和旧 `data/objects`，不自动删除；
3. 准备最终 YAML，显式指定 `nas_data`、`seed_data` 和 `access_mode`；
4. 若目标 `seed_data` 含不兼容旧 schema，使用新的空目录或人工备份后显式重建；
5. 部署一个完成全部 Gate 的新 binary；
6. 新进程启动并执行首次全量扫描；
7. 首次扫描未完成前只能把已完整索引内容标记 available；
8. Gate 全部验证后对外公布新 WS/WSS/WebRTC 地址。

禁止新进程自动删除旧对象目录或默默原地转换未知 schema。检测到不兼容数据时必须用中文错误
拒绝启动，并给出“备份后使用空 seed_data 重建”的明确处理方式。

### 回滚

硬切换回滚单位是整个 release：

- 停止新进程；
- 保留失败现场的 `seed_data` 供诊断；
- 恢复旧 binary、旧配置和旧数据库备份；
- `nas_data` 因为新服务从不写入，不需要回滚。

不允许只回滚 binary 而让旧 binary 写新 schema，也不允许只回滚数据库继续运行新 binary。

## 8. 特殊情况施工处理表

| 场景 | 实现动作 | 验证证据 |
|---|---|---|
| 根目录暂时为空 | 成功扫描后批量转 invalid，不清 Seed | fake clock 显示 24h 内恢复不重算 |
| root Walk 直接失败 | scan failed，全部位置转 invalid，DB/Seed 保留 24h | 不返回 available，不立即清理 |
| 某子树权限失败 | scan partial，该子树位置转 invalid | 其他成功子树仍正常收敛 |
| watcher overflow | 合并一次立即全量扫描 | 指标和扫描记录可见 |
| 文件复制 30 分钟 | 反复 revision/防抖，稳定后只提交最后版本 | 没有半成品 available |
| 24h 内挂载恢复 | 相同指纹 valid，Seed builder 未调用 | Seed inode/hash 保持 |
| 恢复但 mtime/size 变化 | 新 revision 全量 Hash | 新 seed_hash 或重新确认结果 |
| 同路径内容改变但伪造相同 mtime/size | 块 Read Hash 失败、fail closed、触发重索引 | 不输出错误 attachment |
| 相同 Seed 两个路径，一个消失 | 另一路径继续 available | Stat/Read 成功，引用数正确 |
| 所有副本消失 | 内容立即不可用，派生数据保留 24h | Stat 非 available，Seed 仍在 |
| 24h 后仍消失 | 清 DB 引用和无引用 Seed | nas_data 无任何写入 |
| rename 事件乱序 | revision + grace 防止提前 GC | Seed 不重复生成/删除 |
| SQLite executor 队列满 | 背压或稳定 rate_limited/503 | 内存不随请求无限增长 |
| SQLite 事务失败 | 不发布索引，Seed 孤儿延迟清理 | 无半提交 contents/blocks |
| Seed 临时文件截断 | 启动恢复清理 staging | 不对 MSFile 可见 |
| `.seed` 被人工破坏 | integrity/error，不从损坏 Seed 响应 | 重算或明确运维错误 |
| 原文件读取中被截断 | exact read/hash 失败，尝试其他副本 | 仍失败则 integrity_error |
| 原文件超过 128 GiB | Web 状态 unsupported，不生成协议 Seed | 不截断、不 OOM |
| symlink 指向根外 | 跳过并中文记录 | 无路径逃逸读取 |
| 第二实例同 seed_data | service.lock 拒绝启动 | 第一实例继续正常 |
| private 空白名单 | 连接层认证后业务拒绝 | 没有 allow-all 日志或路径 |
| public 大量新公钥 | 全局连接/Read/带宽限制生效 | 换 key 不能绕过全局上限 |
| 管理 API 收到文件 DELETE | 405 | nas_data 文件保持 |
| 管理 API 请求白名单路由 | 404/405 | DB 无 clients 表 |

## 10. 最终验收命令

```bash
cd labs/webrtc-go

go test ./...
go test -race ./...
go vet ./...
go build ./cmd/msfile-nas

```

如果前端增加独立构建步骤，还必须执行 lockfile 对应的 lint/test/build。不得用“单 package 通过”
代替全模块测试。

必须补一次目标 NAS 挂载人工测试：

1. 在挂载中建立多级目录和至少一个跨 256 KiB 的文件；
2. 看到事件快速建立索引；
3. 修改、rename、删除并观察状态；
4. 临时让整个目录不可见，确认只进入 invalid；
5. 24 小时测试使用 fake clock，人工测试不真实等待；
6. 恢复目录，确认 Seed 未重算；
7. 通过 WS/WSS/WebRTC 中至少目标部署需要的路径读取 Seed 和块；
8. 对返回块重新计算 SHA-256；
9. 比对测试前后 `nas_data` 路径、文件数、mtime 和内容摘要，确认服务没有写入。

## 11. 最终验收清单

### 11.1 需求与边界

- [ ] 实现与需求冻结文档逐项一致；
- [ ] 没有遗留未裁决的 TODO、临时 allow-all 或双模式 flag；
- [ ] `nas_data` 是唯一原文件真值；
- [ ] `seed_data` 可以从 `nas_data` 重建；
- [ ] V1 没有 manifest、永久块对象和目录树模型；
- [ ] 挂载监控明确不在项目内。

### 11.2 数据安全

- [ ] 服务运行前后 `nas_data` tree 和文件摘要不变；
- [ ] Web、MSFile、GC、启动恢复均没有删除原文件的代码路径；
- [ ] Seed 使用 staging + fsync + 原子 rename；
- [ ] 无 DB 引用 Seed 不对外可见；
- [ ] 路径规范化阻止越过 `nas_data`；
- [ ] 默认不跟随 symlink；
- [ ] ReadAt exact 长度并逐块验证 SHA-256。

### 11.3 同步与恢复

- [ ] watcher 和周期全量扫描同时存在；
- [ ] 关闭 watcher 后扫描仍最终一致；
- [ ] generation 防止 partial scan 误删，失败范围 fail closed 为 invalid；
- [ ] revision 防止旧 Hash worker 覆盖新文件；
- [ ] stat A/B/C 阻止半成品发布；
- [ ] 第一次 invalid_since 不被后续扫描刷新；
- [ ] 24 小时内同指纹恢复不重算；
- [ ] 24 小时到期只清派生数据；
- [ ] 多位置内容正确引用和回退；
- [ ] overflow、权限错误、持续写入均有中文诊断与恢复路径。

### 11.4 SQLite 竞争控制

- [ ] 全仓只有 indexdb executor 持有底层 SQLite；
- [ ] `MaxOpenConns = 1`；
- [ ] HTTP、MSFile、watcher、scanner、worker 不直接写 SQL；
- [ ] 队列有界且满载行为明确；
- [ ] DB executor 中没有慢磁盘/网络任务；
- [ ] 事务、取消、关闭和 race tests 全部通过。

### 11.5 授权与安全

- [ ] `access_mode` 只能显式 private/public；
- [ ] private 只接受配置文件公钥数组；
- [ ] private 空列表拒绝全部；
- [ ] public 仍要求 libp2p Noise 身份认证；
- [ ] public 有全局资源限额；
- [ ] SQLite 没有 clients/whitelist 表；
- [ ] Web/API 没有白名单 CRUD；
- [ ] 报文自报公钥不参与授权；
- [ ] WSS TLS 不替代 PeerId/Noise 校验。

### 11.6 协议与传输

- [ ] deterministic CBOR 和最短 uvarint 严格校验；
- [ ] Stat/Read 双 stream 和 request ID 生命周期正确；
- [ ] response writer 唯一且 attachment 不交错；
- [ ] invalid 内容不返回 available；
- [ ] Seed 与块都通过 content_hash 返回；
- [ ] WS、WSS、WebRTC Direct 正式服务按目标环境验证；
- [ ] 正式 binary 不注册实验协议为文件服务。

### 11.7 Web 运维面

- [ ] 主列表是 Seed Hash 平面列表；
- [ ] 字段和错误都有中文说明；
- [ ] 能查看 ready/invalid/indexing/error、扫描状态和无效倒计时；
- [ ] 能触发全量扫描；
- [ ] 没有目录树、上传、删除、移动、重命名；
- [ ] 没有白名单页面/API；
- [ ] 不返回绝对路径、私钥或完整白名单；
- [ ] public 模式不自动公开管理面。

### 11.8 运维切换

- [ ] 旧 binary 完全停止后才启动新 binary；
- [ ] 旧 DB/objects 已备份且未被新服务自动删除；
- [ ] 不兼容 schema 会中文报错并拒绝启动；
- [ ] 第二实例会被 service.lock 拒绝；
- [ ] SIGINT/SIGTERM 能有界优雅停止；
- [ ] 回滚同时恢复 binary、配置和匹配的 DB；
- [ ] 最终运行手册包含启动、恢复、清理和排错命令。

## 12. 完工定义

只有同时满足以下条件才可以关闭施工单：

1. 文件级清单全部完成，旧冲突能力已经删除而不是隐藏；
2. T01–T28 全部通过并有可复现证据；
3. 最终验收清单没有跳过项；
4. `go test -race ./...`、构建和目标挂载人工验证通过；
5. 文档、配置示例和实际字段一致且都有中文说明；
6. 通过代码搜索证明没有直接 SQLite 旁路、clients CRUD、object block store 和 Web 原文件写路由；
7. 一次性新 release 可以从空 `seed_data` 扫描现有 `nas_data` 并对外提供正确 MSFile 内容；
8. 回滚不需要恢复或修复 `nas_data`，因为施工后的服务从未写入它。
