# 20260825-1 MSFile NAS V1 需求冻结

> 状态：V1 实现输入。本文冻结 NAS 产品需求、数据真值、同步语义、访问策略和明确非目标。
> `/msfile/1.0.0` 的 wire 与网络行为仍分别以
> [Wire Messages V1](../protocol/wire-messages.zh.md) 和
> [Network Protocol V1](../protocol/network.zh.md) 为真值；本文不重定义报文字段。

## 1. 目标

本项目一次性切换为 Go 实现的 MSFile NAS 服务：

1. 用户继续按目录和子目录管理自己的 NAS 文件；
2. 用户可以把 `nas_data` 挂载为日常使用的 SMB、NFS、WebDAV、FUSE 或本地网盘；
3. 服务不改变原目录结构，把这些原文件转换成 MSFile Proxy V1 可查询、可读取的内容；
4. 服务同时支持 WebRTC Direct、WebSocket 和 WSS 上的 libp2p `/msfile/1.0.0`；
5. 服务支持私有公钥白名单和公共文件服务两种访问模式；
6. 文件事件负责低延迟发现，周期性全量扫描负责最终一致性；
7. SQLite 的所有读写由一个异步数据库执行器串行管控，业务代码不能绕过；
8. Web 管理面只展示平面的 Hash 文件索引和同步状态，不建立或模拟 NAS 目录树。

## 2. 术语与两个数据区

### 2.1 `nas_data`

`nas_data` 是原文件的唯一真值：

```text
nas_data/
├── 电影/
│   ├── movie-a.mkv
│   └── movie-b.mkv
├── 音乐/
│   └── album/song.flac
└── 文档/
    └── report.pdf
```

规范性要求：

- 保留用户已有目录、子目录、文件名和原始字节；
- 服务只读取原文件，不为了 MSFile 改名、移动、切块保存或重排目录；
- 用户通过挂载新增、修改、移动和删除文件，是 `nas_data` 的正常写入来源；
- V1 Web 管理面不得上传、删除、移动或重命名 `nas_data` 原文件；
- MSFile wire 本身也不提供上传、删除、目录和重命名命令。

### 2.2 `seed_data`

`seed_data` 保存从 `nas_data` 派生、可以重建的数据：

```text
seed_data/
├── seeds/
│   └── ab/
│       └── cd/
│           └── <完整 64 位 seed_hash>.seed
├── staging/
├── trash/
├── index.sqlite
└── service.lock
```

各项中文含义：

| 路径 | 中文含义 |
|---|---|
| `seeds/ab/cd/<seed_hash>.seed` | MasterSeed 原始二进制；两级 Hash 前缀只用于分散目录项 |
| `staging/` | 尚未原子发布的临时 Seed |
| `trash/` | 已解除索引、等待安全清理的派生文件 |
| `index.sqlite` | Hash、原文件位置、块偏移和同步状态索引 |
| `service.lock` | 防止两个服务进程同时管理同一 `seed_data` |

规范性要求：

- `seed_data` 必须位于 `nas_data` 外部，禁止把派生文件再次扫描为用户文件；
- V1 不保存 `manifest.cbor` 或其他每文件 manifest；
- V1 不保存独立的块对象文件；
- 删除整个 `seed_data` 后，允许通过重新扫描 `nas_data` 完整重建；
- `seed_data` 丢失不应损坏或改变 `nas_data`。

## 3. MasterSeed 与原文件读取

块与 Seed 算法严格沿用 Wire V1：

```text
BLOCK_SIZE_BYTES = 262144

block_hash[i] = SHA-256(source_block[i])

seed_bytes =
  block_hash[0] || block_hash[1] || ... || block_hash[n-1]

seed_hash = SHA-256(seed_bytes)
```

空文件合法：

```text
source bytes = 0 字节
seed bytes   = 0 字节
seed_hash    = SHA-256(空输入)
```

读取方式冻结如下：

```text
Read(seed_hash)
  -> 从 seed_data 的 .seed 文件返回

Read(block_hash)
  -> SQLite 查询一个 valid 原文件位置、块偏移和长度
  -> 对 nas_data 原文件执行 ReadAt(offset, length)
  -> 校验 SHA-256(bytes) == requested block_hash
  -> 校验成功后返回
```

禁止：

- 为每个块永久生成 `objects/<block_hash>`；
- 从文件名、扩展名或目录猜测 Seed Hash；
- 未校验块 Hash 就返回原文件切片；
- 把 `.seed` 文件路径或 `nas_data` 相对路径放进 MSFile wire。

## 4. 平面 Hash 模型与内部位置映射

MSFile、数据库的内容主键和 Web 主列表都使用 `seed_hash`，不建立目录节点、父子目录表或目录树
API。但是增量同步和块读取必须知道原文件位置，因此 SQLite 可以保存内部相对路径：

```text
电影/movie-a.mkv -> seed_hash
```

内部相对路径不是内容身份，不进入 MSFile wire。V1 Web 文件主列表不得按目录组织，也不得把绝对
磁盘路径返回给浏览器。

推荐逻辑表：

```text
contents
  seed_hash                // 内容唯一标识，64 位小写 hex
  size_bytes               // 原文件尺寸
  recommended_filename     // Stat 建议文件名，通常取一个可用位置的 basename
  media_type               // MIME 类型
  state                    // ready、invalid、indexing、error
  created_at               // 首次索引时间
  updated_at               // 最近状态更新时间

file_locations
  relative_path            // nas_data 内部相对路径，不是 Web 目录模型
  seed_hash                // 指向 contents
  size_bytes               // 上次确认尺寸
  mtime_ns                 // 上次确认修改时间
  device_id                // 文件系统提供时记录
  inode                     // 文件系统提供且稳定时记录
  state                    // valid、invalid、indexing、error
  invalid_since            // 第一次确认不可见的时间；valid 时为空
  last_seen_generation     // 最近一次成功扫描批次号
  last_error_zh            // 中文同步诊断，不含绝对路径之外的敏感信息

seed_blocks
  seed_hash                // 所属 Seed
  block_index              // 从 0 开始的块序号
  block_hash               // 64 位小写 hex
  offset_bytes             // block_index * 262144
  length_bytes             // 1..262144；空文件没有记录

scan_runs
  generation               // 单调递增扫描批次号
  started_at               // 扫描开始时间
  finished_at              // 扫描完成时间
  status                   // running、succeeded、partial、failed
  error_zh                 // 中文诊断
```

相同内容允许存在多个物理位置：

```text
nas_data/电影/a.mkv ───────┐
                           ├── 同一个 seed_hash
nas_data/备份/电影/a.mkv ──┘
```

只要一个 `seed_hash` 至少还有一个 `valid` 位置，它就是可用内容。删除一个位置不能使其他副本
失效，也不能提前删除共享 Seed。

## 5. SQLite 并发模型

V1 必须只有一个数据库入口：

```text
watcher / scanner / hash worker / MSFile / Web
                    │
                    ▼
             有界异步请求队列
                    │
                    ▼
          单个 SQLite executor goroutine
                    │
                    ▼
        唯一 *sql.DB，MaxOpenConns = 1
```

要求：

- 查询、更新、事务、schema migration 都通过执行器；
- 业务包不能取得底层 `*sql.DB`；
- SQLite 开启 WAL、foreign keys 和 busy timeout；
- 队列必须有界，满载时产生背压或明确错误，不能无限占用内存；
- 慢文件 Hash、磁盘 ReadAt、目录遍历不能在 SQLite executor 中执行；
- Hash worker 先完成磁盘计算，再用一个短事务提交新索引；
- 同一路径的旧任务必须通过 generation/revision 防止覆盖更新结果。

禁止用散落的 `sync.Mutex` 包裹多个 `db.Query`/`db.Exec` 冒充统一数据库 API，也禁止让 HTTP、
watcher 和协议服务各自持有 SQLite connection。

## 6. 文件同步模型

### 6.1 总原则

```text
文件事件用于快速发现
周期性全量扫描负责最终一致性
nas_data 是真值
SQLite 和 Seed 都是派生索引
```

只依赖文件事件不合格。SMB、NFS、FUSE、WebDAV 或 watcher overflow 都可能丢事件。

### 6.2 启动扫描

服务取得 `service.lock` 并打开数据库后，必须启动一次全量扫描：

1. 递归遍历 `nas_data`；
2. 只接受普通文件；
3. 默认不跟随符号链接；
4. 为每次扫描分配唯一 `generation`；
5. 与 `relative_path + size_bytes + mtime_ns` 等指纹比较；
6. 指纹未变的文件跳过全量 Hash；
7. 新增、变化或无法确认身份的文件进入稳定性检测和 Hash 队列；
8. 成功扫描范围内未见的文件进入 `invalid`；扫描失败的根或子树因为当前不可读，其中已知位置
   同样进入 `invalid`，但不得直接删除记录或 Seed。

首次建立索引必须读取全部可分享原文件，这是生成 Seed 的必需成本。Hash worker 数量必须可配置，
默认保守为 `1`，防止机械硬盘或低端 NAS 被并发顺序/随机读取打满。

### 6.3 文件事件

watcher 至少处理：

- 文件创建和写入：防抖后进入稳定性检测；
- 文件删除：相应位置进入 `invalid` 候选；
- 文件重命名：旧位置失效，新位置重新确认；
- 新目录：注册递归 watcher；
- 目录删除：目录下旧位置进入失效候选；
- watcher overflow、watch limit 或后端错误：记录中文诊断并立即安排全量扫描。

事件不得直接发布 Seed。多次连续写入同一路径必须合并，旧 Hash 任务必须能被新 revision 淘汰。

### 6.4 稳定性检测

为避免把正在复制的大文件发布出去，计算前后必须检查：

```text
stat A
等待安静期
stat B
A 与 B 的 size/mtime 相同才开始 Hash
完成 Hash
stat C
B 与 C 的 size/mtime 相同才允许提交
```

任一比较失败：

- 丢弃本次临时 Seed；
- 不覆盖旧索引；
- 重新防抖排队；
- 达到重试上限后保留 `indexing/error` 状态并等待下一次事件或全量扫描。

### 6.5 Seed 原子发布

```text
读取稳定原文件
  -> 流式计算 block_hash
  -> staging 写临时 Seed
  -> fsync 临时文件
  -> 计算 seed_hash
  -> 原子 rename 到 seeds/<前缀>/<seed_hash>.seed
  -> SQLite 短事务提交 contents/location/blocks
```

最终 Seed 已存在时复用，不能覆盖为不同字节。SQLite 提交失败产生的孤儿 Seed 可以由后续清理任务
回收，但在没有数据库有效引用前不得对 MSFile 可见。

## 7. 文件失效、24 小时保留与恢复

### 7.1 不做挂载监控

V1 明确不判断：

- NAS 是否挂载；
- 挂载是否断开；
- 挂载点是否退化为空目录；
- 文件是用户删除还是暂时不可见。

项目只观察“当前扫描或打开文件时是否可见、可读”。所有不可见情况统一进入失效保留逻辑。

具体裁决：

- `nas_data` 根目录不存在或无法读取：所有当前位置进入 `invalid`，保留 24 小时；
- 某个子目录无法读取：该子树下的已知位置进入 `invalid`，其他成功范围继续扫描；
- 根目录可以成功读取但内容为空：所有未见位置进入 `invalid`；
- 扫描错误只改变可用状态，绝不能绕过 24 小时保留直接清理派生数据。

### 7.2 状态机

```text
valid
  │ 成功扫描确认路径不可见
  ▼
invalid（记录第一次 invalid_since）
  │
  ├── 24 小时内恢复且指纹一致
  │     -> valid，复用 SQLite 块映射和原 Seed，不重新计算
  │
  ├── 24 小时内恢复但指纹变化
  │     -> indexing，重新计算并切换到新 seed_hash
  │
  └── 连续不可见达到 24 小时
        -> 删除该 location
        -> 没有任何 location 引用时删除 contents/seed_blocks/Seed
```

`invalid_since` 只能在第一次从 `valid` 进入 `invalid` 时设置。重复扫描仍不可见时不得刷新时间。

“恢复且指纹一致”的 V1 判定至少包括：

```text
relative_path 相同
size_bytes 相同
mtime_ns 相同
可靠的 device_id/inode 没有矛盾
```

NAS 文件系统不提供稳定 inode 时，不能仅因 inode 变化强制失败；以路径、尺寸和修改时间为主要
恢复依据。恢复后每次块读取仍必须校验请求 Hash，因此错误复用会 fail closed，并触发重新索引。

### 7.3 可用性

- 至少一个 `valid` location：Stat 可以返回 `available`；
- 所有 location 都是 `invalid/indexing/error`：Stat 不得返回 `available`；
- 原文件不可读时，即使 `.seed` 仍在 24 小时保留期，也不得只出售 Seed 而让全部块不可用；
- Read 时找不到可用位置返回 `content_not_found` 或稳定的存储不可用错误，不能返回损坏字节；
- 另一个相同内容副本有效时，应自动从有效副本读取。

### 7.4 超过 24 小时

达到保留期后只清理派生数据：

- 删除无效 `file_locations`；
- 无其他位置引用时删除 `contents` 和 `seed_blocks`；
- Seed 先原子移动到 `trash`，解除可见引用后异步删除；
- 绝不删除、移动或创建 `nas_data` 原文件。

如果挂载在清理后恢复，该文件作为新发现文件重新计算 Seed。这是“不做挂载监控”的明确代价。

## 8. 重命名、并发修改与读取竞态

### 8.1 重命名

- watcher 能可靠证明同一 device/inode 时，可以只更新 `relative_path` 并复用 Seed；
- 远程挂载的文件身份不可靠时，正确性优先，按新文件重新确认；
- 旧位置仍受 24 小时保留保护，不能因为 rename 事件乱序立即删除 Seed。

### 8.2 Hash 期间变化

- stat C 与 stat B 不同：本次结果无效；
- 同一路径 revision 已更新：旧 worker 即使完成也不得提交；
- 文件消失：进入 invalid，不发布临时 Seed；
- 文件读取权限暂时失败：记录 `error`，不能伪装成永久删除。

### 8.3 Read 期间变化

块 Read 必须：

1. 从一个当前 `valid` location 打开文件；
2. 按记录 offset/length 读取 exact 字节；
3. 校验 SHA-256；
4. 校验失败则丢弃内容、返回 `integrity_error`、将位置标脏并安排重新索引；
5. 禁止把未校验或截断字节写进 ReadResponse attachment。

## 9. 访问模式与配置文件白名单

V1 只支持两个全局模式：

```text
private
  -> 仅允许配置文件白名单中的客户端公钥执行 Stat 和 Read

public
  -> 任意通过 libp2p Noise 认证的 secp256k1 客户端都允许 Stat 和 Read
```

“公共”不表示裸 WebSocket 匿名访问。所有 MSFile 请求仍运行在 libp2p 已认证 connection 上，
远端身份仍取自 connection 的真实压缩公钥。

白名单 V1 只是公钥数组：

```yaml
access_mode: private

public_key_whitelist:
  - "02e940...66位压缩公钥"
  - "03a812...66位压缩公钥"
```

规则：

- 每项必须是 33 字节压缩 secp256k1 公钥的 66 位 hex；
- 首字节必须是 `02` 或 `03`；
- 加载时规范化为小写并去重；
- 任一非法项导致启动失败，不能跳过坏项继续；
- `private` 且列表为空等价于拒绝全部客户端；
- `public` 允许全部已认证客户端，列表不参与判断；
- 白名单不保存到 SQLite；
- 不提供白名单名称、Stat/Read 分权、管理 API 或管理页面；
- V1 修改配置后通过重启生效，不要求热重载。

公共模式没有文件枚举 wire。客户端必须已经知道 Seed Hash 才能 Stat/Read；Web 管理台不能因为
公共模式而对公网匿名开放。公共模式必须配置全局 connection、stream、并发 Read 和带宽上限，
因为攻击者可以生成大量新公钥绕过单公钥限额。

V1 不提供目录 include/exclude 分享规则：`nas_data` 下所有稳定、可读且不超过协议尺寸上限的普通
文件都会进入索引。选择 `public` 即表示这些已索引内容可被任何已认证客户端按已知 Hash 获取；
运维人员必须用独立的 `nas_data` 根控制公开范围。

## 10. 网络服务

必须支持：

```text
WebRTC Direct  /udp/.../webrtc-direct
开发或可信内网 WS  /tcp/.../ws
生产 WSS  /tcp/.../tls/ws
```

要求：

- WS/WSS 是 libp2p transport，不是裸 JSON WebSocket API；
- WSS TLS 不替代 Noise、公钥认证或供应商 PeerId pin；
- 正式公网浏览器路径必须使用 WSS，WS 只允许 loopback 或明确可信网络；
- 只在 `/msfile/1.0.0` 实现正式文件 Stat/Read；
- 不把实验 `/msfile-lab/*` 当成正式服务；
- 每个 connection 的 Stat/Read 双 stream、request ID、CBOR 和 attachment 行为遵守现有协议真值。

## 11. Web 管理面

V1 Web 页面是运维索引面，不是另一个 NAS 文件管理器：

- 平面展示 `seed_hash` 列表；
- 支持按完整/前缀 Hash、建议文件名和状态查询；
- 展示尺寸、媒体类型、可用副本数、同步状态、首次索引时间和最近确认时间；
- 展示全量扫描状态、队列深度、错误数量、有效/无效内容数量；
- 允许管理员触发一次全量扫描；
- 无效内容显示 `invalid_since` 和剩余保留时间；
- 所有字段提供中文含义和中文错误信息。

V1 明确禁止：

- Web 上传到 `nas_data`；
- Web 删除、移动、重命名 `nas_data` 原文件；
- 浏览或编辑 NAS 目录树；
- 白名单管理页面或 API；
- 通过 Web 暴露绝对路径、完整白名单或私钥；
- 把 Web 管理 token 当成 MSFile 客户端凭据。

Web 管理面默认只监听 loopback。非 loopback 部署必须有独立管理认证和可信 TLS 入口，且与
`access_mode=public` 完全无关。

## 12. 配置冻结

配置文件必须支持中文注释，推荐 YAML。字段至少包括：

```yaml
# 原文件根目录；项目不修改其中目录结构
nas_data: "/mnt/nas"

# Seed、SQLite、临时文件根目录；不能位于 nas_data 内
seed_data: "/var/lib/msfile-nas"

# private 或 public
access_mode: private

# V1 只有公钥列表
public_key_whitelist:
  - "02..."

# 周期全量扫描间隔
full_scan_interval: 10m

# 文件连续安静多久才开始计算
file_stable_interval: 3s

# 文件不可见后的派生数据保留时间
invalid_retention: 24h

# 同时读取原文件并计算 Seed 的 worker 数
hash_workers: 1
```

实现可以补充监听地址、TLS 证书、Web 管理监听和资源上限字段，但每个字段必须在示例和文档中有
中文说明。禁止出现“未配置白名单就允许全部”的隐式回退；公开访问只能由显式
`access_mode: public` 开启。

## 13. 特殊情况裁决

| 特殊情况 | 必须行为 | 禁止行为 |
|---|---|---|
| `nas_data` 暂时变空 | 成功扫描后把旧位置设为 invalid，保留 24 小时 | 立即清空 DB 和 Seed |
| `nas_data` 根无法读取 | 所有位置转 invalid，保留 DB/Seed 24 小时 | 继续对外声称 available 或立即清空 |
| 某个子目录扫描报权限错误 | 标记本轮 partial，该子树位置转 invalid 并保留 24 小时 | 立即删除未遍历记录和 Seed |
| watcher 丢事件或 overflow | 记录错误并触发全量扫描 | 假装实时索引仍可靠 |
| 文件持续写入 | 防抖并重试，稳定前不发布 | 对半成品生成 available Seed |
| 文件超过 MSFile V1 最大源文件尺寸 | 标记 unsupported/error 并在 Web 中文展示 | 截断、拆成另一个未定义协议文件 |
| 符号链接 | V1 默认跳过并记录原因 | 跟随到 `nas_data` 外或形成循环 |
| 设备文件、socket、FIFO | 跳过 | 当普通文件读取 |
| 同内容多个路径 | 共用 Seed，任一 valid 即可服务 | 删除一个路径就删除共享 Seed |
| 恢复文件指纹相同 | 复用 Seed，不重算 | 无原因重新读取全部大文件 |
| 恢复文件指纹变化 | 重新计算并生成新映射 | 沿用旧 Seed |
| Read 块 Hash 不匹配 | 返回 integrity_error，位置标脏并重索引 | 返回错误字节或只记录日志继续 |
| SQLite 丢失 | 从 nas_data 重建 | 修改 nas_data 来适配旧索引 |
| Seed 存在但 DB 无引用 | 作为派生孤儿延迟清理 | 仅凭文件存在对外提供 |
| 两个服务指向同一 seed_data | 第二个实例启动失败 | 两实例各自写 SQLite/Seed |
| private 白名单为空 | 拒绝全部客户端 | 自动切换 public |
| public 模式 | 允许所有已认证公钥，实施全局资源限额 | 开放匿名裸 WS 或 Web 管理面 |

## 14. 明确非目标

V1 不实现：

- 挂载状态、文件系统类型或 NAS 在线状态监控；
- 自动挂载、卸载、重连 SMB/NFS/WebDAV；
- 目录浏览协议、目录同步协议或 Web 目录树；
- V1 路径 include/exclude 分享规则；公开范围由独立 `nas_data` 根决定；
- 通过 Web/MSFile 上传、删除、移动、重命名原文件；
- 独立块对象仓库和跨文件物理块去重；
- `manifest.cbor`；
- 白名单数据库、名称、权限细分、管理 UI/API 和热重载；
- DHT 文件发现、公开 Hash 枚举、购买和结算；
- 旧对象存储与新 `nas_data` 模式双写、双读或长期兼容层。

## 15. 需求级验收标准

满足以下全部条件才符合本需求：

- 用户原有多级目录在服务运行前后字节与路径不变；
- 新增、修改、删除和重命名最终都能由全量扫描收敛；
- 文件事件可提前发现变化，但关闭 watcher 后全量扫描仍能独立工作；
- 文件不可见后立即停止提供，DB/Seed 保留 24 小时；
- 24 小时内同路径同指纹恢复不重算 Seed；
- 24 小时后无引用 Seed 被安全回收，原文件从不被服务删除；
- 相同 Seed 的多个原文件位置能互为读取副本；
- Seed 从 `seed_data` 返回，块从原文件 offset 读取并逐块验证；
- SQLite 并发入口只有一个异步执行器；
- private/public 模式均按配置工作，private 不存在 allow-all 回退；
- 白名单只存在配置文件，Web/API/SQLite 均无管理能力；
- Web 是中文平面 Hash 运维界面，没有目录树和原文件写操作；
- WS/WSS/WebRTC Direct 都承载正式 libp2p `/msfile/1.0.0`；
- 任一完整性、扫描、权限或资源异常 fail closed，不返回未经验证的内容。
